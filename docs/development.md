# Development Guide

Day-to-day commands for working on DevTrack locally. For the "why" behind these choices
(layering, migrations-as-a-separate-step, etc.) see [architecture.md](architecture.md); for the
one-command Docker path see the root [README](../README.md#docker).

## Prerequisites

- Python 3.12+
- Node.js 22+
- PostgreSQL 16 (or Docker, to run it in a container instead)

## Backend

```bash
cd backend
python -m venv venv
venv/Scripts/activate        # venv\Scripts\Activate.ps1 on native PowerShell, source venv/bin/activate on macOS/Linux
pip install -r requirements-dev.txt   # includes requirements.txt plus pytest/ruff
cp ../.env.example ../.env   # then edit DATABASE_URL etc.
alembic upgrade head
uvicorn app.main:app --reload
```

The API is now at `http://localhost:8000`, with interactive docs at `http://localhost:8000/docs`.

### Migrations

```bash
cd backend
alembic upgrade head                              # apply all pending migrations
alembic revision --autogenerate -m "short message" # generate a new migration from model changes
alembic downgrade -1                               # roll back one migration
```

Always review an autogenerated migration before running it — autogeneration is a starting point,
not a guarantee of correctness (it won't catch every intent, e.g. data backfills). Migrations are
never run automatically by the app or by Docker Compose on startup; they're a deliberate, explicit
step, both locally and in the `migrate` Compose service.

### Tests

```bash
cd backend
pytest              # runs against an in-memory SQLite database
```

### Lint & format

```bash
cd backend
ruff check .
ruff format .          # or: ruff format --check . to verify without modifying
```

## Frontend

```bash
cd frontend
npm install
cp .env.example .env   # set VITE_API_BASE_URL if not using the default
npm run dev
```

The app is now at `http://localhost:5173`.

### Tests, build, lint

```bash
cd frontend
npm run test
npm run build
npm run lint
npm run format:check   # or: npm run format to apply
```

## Docker (full stack)

```bash
docker compose up -d postgres
docker compose run --rm migrate
docker compose up -d
```

This starts PostgreSQL, applies all migrations, then starts the backend (`http://localhost:8000`)
and frontend (`http://localhost:8080`). See the root README's [Docker](../README.md#docker)
section for the full explanation of why migrations are a separate `run --rm` step rather than
part of `up`.

To stop everything (keeping data): `docker compose down`. To also wipe the database volume:
`docker compose down -v`.

## Common Tasks

| Task | Command |
|---|---|
| Reset local DB from scratch | `docker compose down -v && docker compose up -d postgres && docker compose run --rm migrate` |
| Check container health | `docker compose ps` |
| Tail backend logs | `docker compose logs -f backend` |
| Run one backend test file | `pytest tests/test_issues.py -v` |
| Run one frontend test file | `npm run test -- src/pages/ProjectDetailPage.test.tsx` |
